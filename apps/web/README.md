# Internal data map (apps/web)

Team tool to explore and validate data (front A, not judged). Static site built with Vite, React, TypeScript and MapLibre GL JS, deployed to Cloudflare Pages by [`.github/workflows/deploy-internal-map.yml`](../../.github/workflows/deploy-internal-map.yml). No API and no login: the app reads pre-generated files from `public/data/`.

## Requirements

Node.js 24 (CI uses 24.22.3) and npm.

## Install and run

From `apps/web/`:

```bash
npm ci && npm run dev
```

Then open the URL Vite prints (default http://localhost:5173).

## Lint, typecheck and build

```bash
npm run lint        # ESLint
npm run typecheck   # tsc --noEmit
npm run build       # type-checks, then builds into dist/ (dist/index.html)
npm run preview     # serves the built dist/ locally
```

## Plot view (product dashboard, #62)

The default screen (`src/plot/`): click a point in Sergipe, choose the **last crop grown** separately from the **intended crop**, choose a priority, and compare the three strategies with planting dates, trade-offs, Diagnosis and Projection charts, and the source of every number. The internal data map stays at `/#internal`.

The screen calls only the API (`POST /recommendation`, #53) through `src/plot/api.ts`. Set `VITE_API_URL` (for example `http://localhost:8000`) to use it. The request sends the last crop as `previous_crops` (or an explicit empty list when the history is unknown). A configured API failure is shown as an error; it is never replaced by a saved pilot result.

The API accepts only the supported crop IDs (`maize`, `beans`, `cassava`) in `previous_crops`; unsupported history is rejected. When history is unknown, the engine adds no family-break score and says that a pest-cycle break cannot be assessed.

Without `VITE_API_URL`, the screen uses precomputed pilot runs in `public/demo/`. It labels the pilot, generation date and saved crop history. Those files are not recalculated for a clicked address or a newly selected last crop; the UI states when the selected history differs from the saved run. The seasonal rain risk for an arbitrary point is computed separately from NASA POWER. The PT-BR button switches dashboard labels, units and template text; engine evidence and notes remain in English.

## What the internal map shows

- OpenStreetMap base map, opening on Sergipe.
- Region selector (Sergipe, Nordeste). The bounding boxes in `src/regions.ts` are copied from `src/data/regions.py` at the repo root; keep both files equal.
- Six NASA GIBS layers that can be switched on and off: true color, NDVI, land surface temperature, soil moisture, precipitation and fire hotspots (`src/gibs/layers.ts`, with the source of every identifier).
- One date (UTC) for all layers. The app asks GIBS which dates each layer has (WMTS DescribeDomains), opens on the most recent date that has data in the most layers, and says in words when a layer has no data on the chosen date.
- A legend under each visible layer, drawn from the layer's official GIBS colormap, with its unit.

Network: the browser talks to `tile.openstreetmap.org` and `gibs.earthdata.nasa.gov` only. No key, no login, no API of our own. The fire layer uses the GIBS WMS, because the EPSG:3857 WMTS only lists it as vector tiles and those answer 404.
